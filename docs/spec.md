\## Research question (Part B)

When plans are executed with an Action Dependency Graph (ADG) and robots suffer random delays, do

SOC-optimal CBS plans lose more execution efficiency than prioritized-planning plans? Does the number of

cross-agent dependencies in a plan predict that loss?

\- H1: on instances both algorithms solve, CBS plans degrade more under delays than PP plans.

\- H2: across all plans, degradation increases with cross-agent dependency density.

A null or reversed result is a valid finding. Report whatever the data shows.

\## Step 3: Low-level space-time A\*

\- State is (cell, t). Constraints for one agent:

&#x20; - vertex constraint: (cell, t)

&#x20; - edge constraint: (u, v, t), meaning "may not move u→v arriving at time t"

\- Goal rule: the agent may only finish at its goal at a time t greater than every vertex constraint on its

&#x20; goal cell. Once it finishes, it stays at the goal forever.

\- Use a time horizon cap (e.g. map cells + max constraint time) so infeasible searches end.

\- Path cost = arrival time at the goal, ignoring trailing waits. Sum of costs (SOC) = sum over agents.

&#x20; Use the SOC definitions in Stern et al. 2019.

\- Tests: a path with no constraints equals the BFS length; a vertex constraint forces a wait or detour;

&#x20; a constraint on the goal delays the finish.



\## Step 4: Independent validator (write this before CBS)

\- Pad each path by repeating its goal position until the longest path ends.

\- Check: starts and goals match; every move is to a 4-neighbour or a wait into a free cell;

&#x20; no vertex conflicts; no swap (edge) conflicts.

\- Unit-test it on hand-made valid and invalid solutions.



\## Step 5: Prioritized planning (baseline)

\- Plan agents in scenario order with space-time A\*, against a reservation table of earlier agents' paths.

&#x20; A finished agent reserves its goal forever.

\- If any agent has no path, report failure. No random restarts: keep the priority order fixed so the

&#x20; delay study compares plain PP against CBS.



\## Step 6: CBS (Sharon et al. 2015)

\- High-level node: constraints, paths, SOC, and the number of conflicts.

\- Open list: a priority queue ordered by SOC, ties broken by fewer conflicts, then by insertion order.

\- Loop: pop a node; find its first conflict (vertex or edge); if there is none, return the solution.

&#x20; Otherwise create two children, each adding one constraint to one of the two agents. Replan only that agent.

&#x20; Drop a child if replanning fails.

\- Record: high-level nodes expanded, low-level searches run, wall time. Add a wall-clock time limit.

\- Correctness tests:

&#x20; - a corridor swap that forces one agent to wait or use a side pocket;

&#x20; - two agents crossing;

&#x20; - an optimality check: on tiny maps (about 4x4) with 2–3 agents, compare CBS SOC against a brute-force joint

&#x20;   A\* over the joint state space. They must be equal.

&#x20; - every CBS output passes the validator.

\## Step 9: Action Dependency Graph (`mapf/adg.py`, after Hönig et al. 2019)

\- Convert each agent's path into move actions only, dropping waits.

&#x20; Action k of agent i = (start cell s, goal cell g, planned start time t), where t is the timestep the move

&#x20; starts in the original plan.

\- Type-1 edges: consecutive actions of the same agent, (i, k) → (i, k+1).

\- Type-2 edges: for agents i ≠ j, add (i, k) → (j, l) if s(i,k) == g(j,l) and t(i,k) <= t(j,l).

&#x20; Meaning: j may only move into a cell after i has moved out of it, in the order the plan used.

&#x20; Build these per cell (group actions by the cells they leave and enter) so the cost does not grow

&#x20; with every pair of actions on the map.

\- Coupling metrics per plan: number of Type-2 edges, Type-2 edges per action (the "density"), and the number

&#x20; of agents linked to at least one other agent.

\- Tests:

&#x20; - two agents that never share a cell give zero Type-2 edges;

&#x20; - a corridor follow (j enters the cell i just left) gives exactly the expected edge;

&#x20; - the ADG is acyclic for every validated benchmark solution (check with a topological sort).



\## Step 10: Delay experiments (`mapf/execution.py`, `experiments/run\_delays.py`, `analyze\_delays.py`)

\### Simulator

\- Discrete time. Each move action takes one timestep.

\- At each timestep, an agent may start its next action only if all its ADG predecessors are complete.

\- Delay models:

&#x20; - Per-step (primary): an agent that is ready to start an action is frozen for that timestep with

&#x20;   probability p. p in {0, 0.05, 0.1, 0.2, 0.3}.

&#x20; - Burst (secondary, cuttable): an agent that is ready is frozen for D = 5 timesteps with probability p.

\- Executed cost of an agent = the timestep its last action completes. Executed SOC = sum over agents.

\- Deadlock guard: if no agent can make progress for 1,000 consecutive steps, raise an error. A correct ADG

&#x20; never deadlocks, so this indicates a bug and must never happen in reported runs.



\### Execution checker

\- Every simulated trace must have no two agents in the same cell at the same timestep and no swaps.

\- Tests:

&#x20; - with p = 0, the trace is valid and executed SOC <= planned SOC

&#x20;   (it can be lower because waits were dropped);

&#x20; - with p > 0, a hand-made corridor case produces the expected waiting behaviour.



\### Metric

\- Degradation(p) = executed SOC at p / executed SOC at p = 0, minus 1, averaged over trials.

&#x20; Compare against the p = 0 execution, not the planned SOC, so that dropping waits does not distort the result.

\- R = 30 delay trials per (solution, p). Seed = hash of (map, scen, k, algorithm, p, trial), recorded in the CSV.



\### Runs

\- Use every solution saved in Step 7 where both CBS and PP succeeded (paired instances).

\- Write `results/delays.csv`, one row per (solution, p, trial):

&#x20; map, scen, k, algorithm, p, model, trial, seed, planned\_soc, exec\_soc, exec\_soc\_p0, degradation,

&#x20; type2\_edges, type2\_density.



\### Analysis (reads the CSVs only)

\- Plot: median degradation vs p, one line per algorithm, one panel per map, with interquartile range.

\- Plot: Type-2 density vs degradation at p = 0.1, all plans, coloured by algorithm.

\- H1 test: for each p, paired Wilcoxon signed-rank test on per-instance mean degradation (CBS vs PP).

&#x20; Report the median paired difference and the p-value.

\- H2 test: Spearman correlation between Type-2 density and degradation at each p, overall and per algorithm.

&#x20; Also report correlation with k, so a reader can see whether density only proxies for crowding.

\- Write `results/delay\_summary.md` with these tables, generated by code.
